Выбери лучший target или anchor для change request codecollector.

Верни только один валидный JSON-объект без markdown, комментариев и текста вне JSON.
Не используй trailing comma. Не закрывай верхний JSON-объект до последнего поля.

Главная задача rerank: выбрать candidate_id из candidate_cards. Не пересказывай search plan и не пиши длинные рассуждения.
Все reason-поля должны быть короткими: одна строка до 160 символов.

JSON-формат ответа:
{
  "recommended_candidate_id": "candidate id or null",
  "recommended_target": "qualname or null",
  "recommended_operation": "replace_symbol | insert_after_symbol | unknown",
  "operation_confidence": 0.0,
  "insert_scope": "module_body | class_body | unknown",
  "expected_new_symbol_kind": "function | class | method | unknown",
  "parent_qualname": "qualname or null",
  "target_role": "target | anchor | method_anchor | parent_class | dependency | unknown",
  "target_confidence": 0.0,
  "target_reason": "коротко",
  "manual_review_required": false,
  "warnings": [{"code": "string", "message": "string"}],
  "ranked_candidates": [
    {"candidate_id": "string", "rank": 1, "reason": "коротко"}
  ],
  "alternatives": [{"candidate_id": "string", "reason": "коротко"}]
}

Правила выбора:
- mentioned_symbols — это символы из индекса проекта, которые были упомянуты в запросе. Их роль неизвестна: это может быть target, вызываемый метод, зависимость, ограничение, пример или нерелевантная ссылка. Само упоминание символа не означает, что его нужно менять.
- Роль упомянутых символов определяй только по полному запросу и context candidate_cards.
- recommended_candidate_id и ranked_candidates должны ссылаться только на candidate_id из candidate_cards.
- Если правильного target/anchor нет среди candidate_cards, верни recommended_candidate_id=null, recommended_target=null и manual_review_required=true.
- Если user_operation задана, не меняй её молча. Если она кажется неверной, сохрани её в recommended_operation и добавь warning.
- Для replace_symbol выбирай существующий symbol, который непосредственно нужно заменить целиком.
- Для insert_after_symbol выбирай anchor-symbol: место, рядом с которым нужно добавить новый function/class/method.
- Для insert_after_symbol + module_body target_role должен быть "anchor".
- Для insert_after_symbol + class_body target_role должен быть "method_anchor" или "parent_class".
- Если запрос просит использовать существующий метод, этот метод может быть dependency/callee, а не target. Target должен быть местом, где меняется код.
- Если запрос просит кнопку, toolbar, action, menu или подключение обработчика, ищи candidate с UI setup/action code: QToolBar, addToolBar, addAction, QAction, triggered, connect.
- Если запрос просит не создавать новый метод, не выбирай insert_after_symbol без явного основания; предпочитай replace_symbol существующего setup/handler метода или manual_review_required=true.
- Если candidate является нужной зависимостью, но не местом изменения, укажи его ниже в ranked_candidates, но не делай recommended_target.
- ranked_candidates должен содержать до 5 лучших candidate_id для ручной проверки.
- Первый ranked_candidates должен совпадать с recommended_candidate_id, если recommended_candidate_id не null.

Входные данные:
$payload_json
